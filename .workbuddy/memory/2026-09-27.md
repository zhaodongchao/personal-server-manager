## 密码登录接入人机校验 + i18n 文案显示原始 key 修复（待提交）

**① i18n 根因：应用自定义 `authentication.*` 文案全部不生效（登录/注册页显示 `authentication.registerSubtitle` 这类原始 key）**
- **根因**：`packages/locales` 的 `loadLocalesMapFromDir` 会把 JSON **按文件名再包一层**——
  `locales/langs/zh-CN/page.json` 的内容最终落在 `messages.zh-CN.page.*`，而不是根级。
  所以本项目 `page.json` 里的三组文案实际都是 `page.auth.*` / `page.dashboard.*` / `page.authentication.*`。
  `router/routes/core.ts`、`layouts/basic.vue` 一直**正确**用 `$t('page.auth.profile')` 等；
  但各 view 用的是 `$t('authentication.xxx')`（根级）→ 查不到 → 回落成 key 原文。
- **能查到的是框架的**：`packages/locales/src/langs/*/authentication.json` 提供根级 `authentication.*`
  （`username/password/usernameTip/verifyRequiredTip/sendCode/codeTip/...`），所以**只有应用自定义的那些**
  （`registerSubtitle/registerSuccessDesc/codeSubtitle/mailCodeSent/captchaTitle/usernameTaken/...`）显示成编码。
- **修法（不改一行业务代码）**：把 `page.json` 里的 `authentication` 对象**整体搬出**，
  新建 `locales/langs/{zh-CN,en-US}/authentication.json`。文件名即命名空间 → 落到根级 `authentication`，
  并与框架的 `authentication` **深合并**（`setLocaleMessage`(框架) → `mergeLocaleMessage`(应用)）。
  `page.json` 只留 `auth`+`dashboard`（`page.auth.*` 调用点不动）。
- **两处重复键是有意覆盖**（应用值在后、胜出）：`mobileLogin` 由框架「手机号登录」→「邮箱验证码登录」；

- **排查口诀**：怀疑某个 key 没生效，先看它属于哪个文件——`page.json` 的必须带 `page.` 前缀，
  想用根级就单独建一个同命名空间名的 json 文件。
