**验证结果（本机环境受限的处理办法，可复用）**：
- 本机只有 JDK17、装 JDK21 网络太慢（下载到 52MB/190MB 超时失败）→ **无法跑 `mvn compile`**
- 替代验证：用 JDK17 `javac` + argfile 精确编译「新增 OAuth 文件 + 最小依赖闭包」，
  `-processorpath` 指向 m2 里的 lombok（否则隐式编译的类拿不到 Lombok 生成的 getter），
  `-cp` 用 `find ~/.m2 -name '*.jar'` 拼出（470 个 jar）+ 单独下载的 JustAuth jar → **0 错误，全部新类产出 class**
- 注意：全模块编译会卡在 3 处 `Thread.ofVirtual()`（Java 21 API），与本次改动无关，需避开而非修复
- 前端 `node_modules` 未安装、无 pnpm → **未做类型检查/构建**，需在装完依赖后跑 `pnpm build:antd`

**排查：登录页看不到第三方入口**
- 原因不是 bug：按配置启用，未配 client-id → `providers` 返回 `[]` → 前端 `v-if="providers.length > 0"` 整块不渲染
- 定位命令：`curl /api/v1/auth/oauth/providers` 返回 `[]` = 未启用；返回 401 = 白名单没生效
- 已为可排查性加日志：`use-oauth.ts` 与 `oauth-setting.vue` 的 catch 分别 `console.warn`（接口没通），
  providers 为空时 `console.info`（接口通但没启用平台）——两种场景界面表现相同，只能靠日志区分
