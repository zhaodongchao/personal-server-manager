## 二、根因与总体方案

| 项 | 内容 |
| --- | --- |
| 根因 | 面板容器（eclipse-temurin:21-jre）内没有 `systemctl` / `journalctl` / `ufw` / `df`，三个模块在容器内执行系统命令注定失败 |
| 方案 | 宿主执行通道 `psm-hostagent`：AF_UNIX socket + 共享密钥 + 28 操作白名单 + argv 数组（无 shell） |
| 日志 | 短轮询 1.5s（不引入 SSE/WebSocket，`EventSource` 无法带 `Authorization` 头） |
| 防火墙看门狗 | 全局开关类操作默认挂 `systemd-run --on-active=N`，超时未确认自动回滚 |
| 表格 | 三页统一 VXE-Table（与用户管理一致） |

## 三、各阶段落地情况

### S0 宿主执行通道 ✅

- `ops/hostagent/hostagent.py` + `install.sh`（安装后自动重启、`RuntimeDirectoryPreserve=yes` 保证 socket inode 稳定）。
- 后端 `HostChannelService` 统一入口，能力快照 `/ops/host/capability` + 主动重探 `/ops/host/probe`。
- 前端三页共用 `HostChannelBanner`（通道状态 + 安装指引），不可用时只读降级。

### S1 服务管理 ✅（验收 15/15）

- 列表改分页 `/ops/service/page`；新增 `failed` / `summary` / `protected` / `detail`（结构化四块）/ `logs` / `daemon-reload` / `batch`。
- **修复**：单元名校验放宽（systemd 把 `-` 转义成 `\x2d`，根挂载点 `-.mount` 以 `-` 开头）。
- **修复**：批量 `systemctl show` 会被模板单元（`autovt@.service`）**整体中止**——先过滤模板单元，批次失败再二分到单单元。实时字段非空率从 5/50 提升到 14/50（MainPID）、35/50（状态时间戳）。

### S2 计划管理 ✅（验收 16/16）

- 命令经宿主通道真实执行（此前「CRUD 可用、执行必失败」）；`splitCommand` 支持引号分词。
- 退出码语义 `0/-1/-2(超时)/-3(跳过)`；超时实测 `journalctl -f` + 2s → `-2` 且 `timedOut=1`。
- 并发互斥原子抢占、`misfirePolicy` / `overlapPolicy` / `maxFail` 失败自愈（实测 maxFail=1 执行一次后自动停用）。
- 表达式预览（cron-utils 中文描述 + 未来 5 次）、命令白名单（含宿主机可用性探测，修正后 18/20 可用）。
- 日志：单条轮询跟随、Blob 下载、按结果筛选、按任务保留清理。

### S3 防火墙管理 ✅（验收 23/23）

- **解析修正**：动作与方向拆成两个字段，消除「来源 = IN 172.238.101.222」污染；55 条规则（29 IPv4 + 26 IPv6）全部可解析，形态分布 any=1 / port=52 / range=2。
- **删除改为编号 + 指纹**（`to|action|from`），指纹不符 → `5014`，防止编号漂移误删。
- **IPv6 成对规则一并处理**：ufw 一次 add 写入本体 + `(v6)` 副本两条，删除时按同指纹连副本一起删，并先删大编号再删小编号（每次删除会重排编号）。
- **生存线 L3**：deny SSH / 面板端口需键入 `SSH 22` / `PANEL 3000`；停用需 `DISABLE`；回滚需 `ROLLBACK`。
- **快照回滚**：每次写操作保存前后快照与结构化 diff，历史抽屉两栏对照 + 一键回滚；已回滚记录再回滚 → `5017`。
- **看门狗**：全局开关挂倒计时，宿主机侧自动回滚。

## 四、验收过程中发现并修复的缺陷

| # | 缺陷 | 严重度 | 修复 |
| --- | --- | --- | --- |
| 1 | 批量 `systemctl show` 被模板单元整体中止，实时字段整片为 null | 高 | 模板单元过滤 + 批次二分降级 |
| 2 | `host.probe` 把「没探测」当「不存在」，白名单误报 4/20 可用 | 中 | probe 同时探测 EXEC_WHITELIST → 18/20 |
| 3 | **回滚脚本把单端口误判成多端口**：`TO_MULTI` 的 `[\d,]+` 也能匹配 `39999/tcp`，回滚脚本写成 `ports:[39999]`，宿主代理回「端口 必须是整数」——**删除后的撤销路径一直是坏的** | 高 | `specFromRule` 补逗号判断，与 `toKind` 同一口径 |
| 4 | 应用名规则（`Nginx HTTP`）还原不出命令行，却仍生成非法 spec | 中 | 无法还原 → `rollbackable=0`，界面置灰 |
| 5 | **一次 add 产生 IPv4/IPv6 两条，按编号删只删一条**，留下看不见的半条规则 | 高 | 同指纹连副本一并删除，先删大编号；前端确认弹窗明示「存在 IPv6 副本（#n），将一并删除」 |
| 6 | 版本徽标拼出「vufw 0.36.2」 | 低 | 去掉 `v` 前缀 |

> #3、#5 是端到端验收打真实接口才暴露的——只看代码、只跑编译发现不了。
> 这也再次印证：**防火墙这类模块的「撤销路径」必须实测走通，不能默认它是对的。**

## 六、遗留事项与建议

1. **面板端口 8080 无放行规则**（生存线已在页面上以红色告警提示）：当前默认入站 deny，
   一旦有人收紧策略（或 ufw 重置），面板会失联。建议在面板上放行 8080/3000，或改用
   22 端口上的 SSH 隧道访问。
2. **`application.yml` 仍以明文提交数据库/Redis 凭据**：应改为环境变量注入（重构前已存在的问题，本次未动）。
3. **git 工作区 `backend/server-boot/src/main/resources/static/` 的产物改动**长期未提交，
   建议把该目录加入 `.gitignore`（构建产物不应入库）。
4. **firewalld 分支未实测**：宿主机是 Debian + ufw，`firewalld` provider 路径只做了接口抽象，
   建议在 CentOS 机器上补一轮验收。
5. 看门狗手动挂载接口（`POST /guard/watchdog`）到期动作是「停用防火墙」，仅用于自救；
   页面未提供入口，属有意保留的后端能力。
