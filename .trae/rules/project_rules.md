# project_rules.md — ServerPanel 项目级强制开发规则

> 本文档为**强制纪律**。Trae 生成任何代码前必须完整读取并严格遵守，任何违反视为无效输出。规则覆盖后端 Java（Spring Boot）与前端 Vue（Vben Admin / TypeScript）全栈，可在全仓结合各智能体角色约束执行。仅写开发规则，不重复项目概要。

## 1. 通用 AI 执行纪律

- **先读后改**：修改任何代码前，必须先读取对应文件完整上下文，禁止断章取义式局部修改；改动位置与周边代码存在耦合时，须一并理解依赖关系。
- **分步实施**：大范围代码改动必须先拆分任务、分步实施，禁止一次性全量替换文件；每一步完成后自检再进入下一步。
- **生成后自检**：生成代码后必须自检三个方面——语法正确性、规范符合性、业务逻辑合理性；存在编译/类型/构建错误时禁止直接提交或交付。
- **语言约定**：所有代码注释、文档说明、日志文案统一使用简体中文；技术术语、类名、方法名等保留英文。
- 遵守本规则的同时，须遵守 `AGENTS.md` 中定义的各智能体职责边界与分层纪律。

## 2. 后端开发强制规则（Spring Boot / Java）

### （1）分层架构红线

- 严格遵循 `Controller → Service → Mapper → Database` 单向调用链；禁止跨层调用（Controller → Mapper）、禁止循环依赖。
- Controller 层仅负责请求接入、参数校验、响应封装（统一 `R<T>`），**禁止**编写业务逻辑。
- Service 层承载业务逻辑与事务控制，**禁止**直接操作 Web 层对象（如 `HttpServletResponse` 透传业务）。
- Mapper 层仅负责数据库交互（MyBatis-Plus / SQL），禁止业务逻辑渗透到持久层。
- 模块依赖只允许单向：`server-boot` 装配各业务模块；业务模块可依赖 `server-framework` / `server-common`，禁止业务模块间反向依赖形成环。

### （2）编码强制规范

- 命名遵循《阿里巴巴Java开发手册》：类名大驼峰、方法名/变量名小驼峰、常量全大写下划线分隔；布尔字段避免 `is` 前缀歧义。
- 类、公共方法、复杂逻辑片段必须添加清晰中文注释；注释说明"为什么"而非复述代码。
- **禁止吞异常**：catch 后必须携带业务上下文（参数、操作、场景），不打印 meaningless 堆栈；统一通过 `ServiceException` + `ErrorCode` 向上抛出，由 `GlobalExceptionHandler` 统一拦截。
- 日志级别统一：DEBUG（调试）、INFO（业务流程）、WARN（可恢复异常）、ERROR（异常与故障）。**使用 SLF4J 占位符**，禁止字符串拼接；敏感信息（密码、Token、密钥、手机号关键位）必须脱敏；禁止输出大对象全量日志。

### （3）接口开发规范

- 遵循 RESTful 命名（名词复数资源 + HTTP 方法语义：GET 查询 / POST 创建与无幂等动作 / PUT 更新 / DELETE 删除），Controller 统一 `@RestController` + `/api/v1` 前缀。
- 全局统一返回体 `R<T>`；错误码全局统一（见 `server-common` 的 `ErrorCode`），禁止各接口自行定义错误语义。
- 入参校验强制使用 JSR-380 注解（`@Valid` / `@Validated` + `@NotBlank`/`@NotNull`/`@Size`/`@Pattern` 等），禁止手动硬编码校验逻辑；复杂校验在 Service 层内聚。
- 全局异常统一处理：业务异常与系统异常分类返回；未知异常兜底返回统一包装并记录 ERROR 日志（脱敏）。

### （4）数据库操作规范

- **禁止 `SELECT *`**，必须明确指定查询字段（MyBatis-Plus `select()` / Lambda 指定列）。
- 列表接口必须强制分页（`PageQuery`/`PageResult` + 分页插件），禁止无分页全量查询。
- 必须使用参数化查询；MyBatis XML 一律使用 `#{param}`，**禁止字符串拼接 `${}`**（动态表名等确需场景须白名单校验）。
- 联表原则上不超过 3 张；查询走索引（WHERE 列需建索引、避免函数/隐式转换破坏索引）；禁止大事务/长事务（事务内禁止远程调用、循环写库）；批量操作用批处理。
- 禁止硬编码表名与字段名，统一通过 `@TableName` / `@TableField` 实体映射；字段变更同步更新对应 DTO/实体与前端字段。

### （5）安全强制约束

- 所有入参必须经过合法性校验，防范 SQL 注入、XSS；文件类入参（路径）必须经过白名单/路径穿越校验（参照 `server-file` `PathGuard`）。
- 敏感数据必须脱敏存储（如密码 BCrypt 哈希，禁止明文）与脱敏输出。
- 接口必须经过权限校验（Sa-Token 鉴权 + 授权校验），禁止越权访问；越权/未授权访问统一拦截返回。

### （6）配置与依赖规范

- 禁止硬编码业务常量与魔法值，统一收敛至常量类（`server-common` 常量包）或配置文件。
- 敏感配置（口令、密钥、连接串）禁止明文写入代码库；生产环境通过环境变量或配置中心注入，本地默认值仅限开发环境。
- 新增第三方依赖必须说明必要性、功能与协议合规性，并在 `pom.xml` 收敛版本管理；引入前评估其安全与许可证风险。

## 3. 前端开发强制规则（Vue / TypeScript，Vben Admin）

### （1）分层架构红线

- 严格遵循职责边界，禁止跨层混乱引用。
- **基础组件与业务组件强制分离**：无业务语义的通用基础组件置于基础层（`packages` / 共享 `components`），**禁止**基础组件包含业务逻辑或依赖业务状态。
- 页面层仅做页面级组合逻辑；业务逻辑下沉至 `store`（Pinia）或 `composables`，禁止在视图内堆积复杂逻辑。
- 接口请求统一由 `api/request.ts` 及 `api` 层管理，**禁止**页面/组件直接发起 axios 原生请求。
- 禁止直接跨模块修改 Pinia 状态，必须通过对应模块的 action 方法；`store` 按业务模块拆分，禁止单模块状态臃肿。

### （2）组件开发规范

- 组件文件大驼峰命名，组件名与文件名一致；优先使用 Composition API（`<script setup lang="ts">`）。
- `props` 必须显式声明 `type`、`default`、`required`（使用 TS 类型 + `withDefaults`），禁止无类型 props。
- 事件通过 `emits` **显式声明**，命名使用短横线（kebab-case）语义词，禁止 `update:xxx` 之外的魔法事件滥用。
- 逻辑复用优先封装为 composables（`useXxx`），禁止复制粘贴式复用。
- 统一组件内书写顺序：`imports → defineOptions → props/emits → setup 状态/computed/watch → 事件处理 → 模板`。

### （3）状态与路由规范

- Pinia 按业务模块拆分（`src/store`、`packages/stores`），禁止单模块状态臃肿；只读共享数据可用组合式封装。
- 路由配置按业务模块拆分（`src/router`），权限路由统一由路由守卫（`guard.ts`/`access.ts`）处理。
- 禁止冗余守卫逻辑：全局守卫负责全局前置（登录态、Token、全局权限），路由独享守卫负责局部权限，职责分层不重叠。

### （4）接口与请求规范

- 必须使用项目封装统一请求工具（`src/api/request.ts` 或 `@vben/request`），禁止直接调用原生 axios。
- 接口地址统一在 `src/api` 目录按业务模块管理，**禁止**在页面/组件内硬编码 URL。
- 统一配置请求/响应拦截器：Token 自动携带、错误统一处理（code 判断 + 提示 + 401 跳转）、取消重复请求等。
- 接口响应数据必须定义对应 TypeScript 类型，**禁止**使用 `any`；枚举、返回体、请求体单独维护类型。

### （5）样式与适配规范

- 组件强制 `scoped` 样式隔离（`<style scoped lang="scss">`），禁止全局样式污染；需影响子组件或全局时先加载动态样式工具。
- CSS 类名采用语义化命名或 BEM 规范，禁止滥用标签选择器与 `!important`。
- 遵循响应式适配原则，以设计稿基准尺寸开发（本项目基于 Tailwind CSS + CSS 变量体系）。
- 通用样式值优先使用 CSS 变量 / 设计体系 token（`packages/styles`、`@core` 设计变量），禁止散落魔法样式值。

### （6）安全与性能约束

- **禁止使用 `v-html` 直接渲染用户输入**，防范 XSS；富文本必须经过清洗策略。
- 敏感数据前端展示必须脱敏；**禁止**将敏感信息明文持久化到本地存储（localStorage / cookie）。
- 图片懒加载、路由懒加载（模块动态 import）、大组件按需拆包/拆分加载；列表、图表等重场景启用懒与虚拟化（vxe-table 等）。
- 引入第三方依赖前必须校验安全性（供应链审计、许可证），并说明必要性。

### （7）配置与依赖规范

- 业务常量与环境变量统一管理，禁止在业务代码中硬编码接口路径、APP 标识等。
- 前端环境变量必须符合构建工具前缀规范（`VITE_` 前缀），非 `VITE_` 开头的变量不会注入到构建产物。
- 新增依赖必须说明必要性；定期审计依赖安全（`pnpm audit`）与版本兼容性（catalog + overrides 收敛版本）。

## 附：违规处理

- 违反上述任一强制项的输出视为无效，编码前须先行修正。
- 涉及分层、安全、依赖新增等红线项时，优先与对应智能体角色（架构师/ DBA / Tester / Opser / Aler）协同确认后再落地。
